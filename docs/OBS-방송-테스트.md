# OBS 오버레이 실제 방송 테스트 절차

RUST WAR NEWS 오버레이를 실제 송출 전에 점검하는 순서입니다. 방송 1시간 전에 진행하는 것을 권장합니다.
소요 시간: 약 20~30분 · 필요 인원: OBS 담당 1명 + 관리자 화면 담당 1명 (1명이 두 화면을 같이 봐도 됨)

## 0. 준비물

- OBS Studio 30 이상 (브라우저 소스 내장)
- 관리자 계정 (OPERATOR 또는 EDITOR 역할) — 임시 비밀번호 상태면 먼저 `/account/password` 에서 변경
- 사이트 상태 확인: `https://rust-war-news.vercel.app/api/health` 가 `"ok": true` 인지 확인
- 테스트 중 시청자에게 노출되지 않도록 **OBS 에서 송출(방송 시작)은 하지 않은 상태**로 진행하거나, 플랫폼의 비공개/테스트 방송을 사용

## 1. OBS 브라우저 소스 등록 (최초 1회)

테스트 전용 장면(예: `RWN 테스트`)을 만들고 아래 6개 소스를 추가합니다.

| 소스 이름 | URL | 너비×높이 |
| --- | --- | --- |
| RWN 속보 | `https://rust-war-news.vercel.app/overlay/breaking` | 1920×1080 |
| RWN 티커 | `https://rust-war-news.vercel.app/overlay/ticker` | 1920×1080 |
| RWN 헤드라인 | `https://rust-war-news.vercel.app/overlay/headline` | 1920×1080 |
| RWN 하단 자막 | `https://rust-war-news.vercel.app/overlay/lower-third` | 1920×1080 |
| RWN 전쟁 현황 | `https://rust-war-news.vercel.app/overlay/war-status` | 1920×1080 |
| RWN 대기 화면 | `https://rust-war-news.vercel.app/overlay/standby` | 1920×1080 |

각 소스 속성에서:

- [ ] 너비 1920, 높이 1080
- [ ] "사용자 지정 CSS" 칸은 **비워 둠** (배경은 이미 투명)
- [ ] "OBS에서 보이지 않을 때 소스 종료" **끔** (켜 두면 장면 전환 때마다 새로 로딩되어 늦게 뜸)
- [ ] "장면이 활성화되면 브라우저 새로 고침" 끔
- [ ] 캔버스 해상도(설정 → 비디오 → 기본 해상도)가 1920×1080 인지 확인. 다르면 소스를 캔버스 크기에 맞게 늘림(우클릭 → 변환 → 화면에 맞추기)

> 레이어 순서(위→아래) 권장: 대기 화면 / 속보 / 헤드라인 / 하단 자막 / 전쟁 현황 / 티커 / 게임 화면

## 2. 점검 항목

관리자 화면 `/admin/overlays` 와 `/admin/control-room` 을 옆에 띄워 두고 진행합니다.
**반영 시간 기준: 관리자 화면에서 바꾼 뒤 약 4초 이내** (5초 넘게 걸리면 9번 문제 해결 참고)

### 2-1. 투명 배경
- [ ] 게임 화면(또는 색 배경) 위에 6개 소스를 올렸을 때 오버레이 외 영역이 **완전히 투명**한가
- [ ] 흰 박스/검은 박스로 화면이 덮이지 않는가

### 2-2. 대기 화면
- [ ] `/admin/episodes` 에 예정 회차가 있으면 회차 제목·카운트다운이 보이는가
- [ ] `/admin/overlays` → 대기 화면 → **수동**, 제목·안내 문구 입력 → "송출에 반영" → OBS 에 반영되는가
- [ ] "즉시 끄기" → OBS 에서 사라지는가 → 다시 **자동**으로 돌려 둠

### 2-3. 속보 배너 (가장 중요)
1. [ ] `/admin/breaking` 에서 테스트 속보 작성 → 제목 `[테스트] 오버레이 점검`, 구분 **긴급**, 확인 상태 **미확인**, "OBS 노출" 체크 → **즉시 송출**
2. [ ] OBS 에 빨간 "긴급 속보" 배너 + 노란 "미확인" 표시가 뜨는가
3. [ ] 같은 속보에서 **정정** → 제목 끝에 `(정정)` 추가, 확인 상태 **확인 완료** → OBS 에 정정 내용과 파란 "정정" 표시가 뜨고 "미확인"이 사라지는가
4. [ ] **OBS 끄기** 버튼 → 사이트에는 남고 OBS 배너만 사라지는가 → 다시 **OBS 켜기**
5. [ ] **종료** → OBS 에서 배너가 사라지는가
6. [ ] 긴 제목(40자 이상)으로 한 번 더 송출 → 글자가 화면 밖으로 잘리지 않는가 → 종료

### 2-4. 하단 티커
- [ ] 송출 중 속보·최신 기사 제목이 오른쪽→왼쪽으로 흐르는가
- [ ] 수동 모드에서 문구 2~3줄 입력 → 반영 → 자동으로 복귀

### 2-5. 헤드라인 · 하단 자막(진행자)
1. [ ] `/admin/episodes` 에서 테스트 회차 생성(진행자 난워니·김옥독 배정) → 큐시트 항목 2개 추가(담당 진행자를 서로 다르게)
2. [ ] **방송 시작** → 사이트 상단에 LIVE 표시가 뜨는가 (테스트 후 반드시 종료)
3. [ ] 지통실에서 **다음 진행 ▶** → 헤드라인에 첫 항목 제목, 하단 자막에 담당 진행자 이름이 뜨는가
4. [ ] 다시 **다음 진행** → 헤드라인·자막이 두 번째 항목/진행자로 바뀌는가
5. [ ] 지통실에서 진행자 전환(드롭다운) → 하단 자막 이름이 바뀌는가
6. [ ] 대기 화면이 방송 중에는 자동으로 숨겨지는가

### 2-6. 전쟁 현황판
- [ ] `/admin/teams` 에서 팀 점수 +1 → 현황판 순위·막대가 바뀌는가
- [ ] 비공개 팀이 현황판에 나오지 않는가

### 2-7. 지연·안정성
- [ ] 10분간 띄워 두고 화면이 멈추거나 사라지지 않는가 (폴링 4초)
- [ ] OBS 에서 소스 우클릭 → "새로 고침" 후 2~3초 안에 다시 뜨는가
- [ ] 인터넷을 잠깐 끊었다 연결 → 자동으로 다시 갱신되는가

## 3. 정리 (꼭 수행)

- [ ] 테스트 회차 **방송 종료** — "아카이브에 공개" 체크 **해제**
- [ ] 사이트 LIVE 표시가 꺼졌는지 확인 (`/admin/settings`)
- [ ] 테스트 속보가 모두 **종료/취소** 상태인지 확인 (`/admin/breaking` → 진행 중 목록이 비어 있어야 함)
- [ ] 6개 오버레이가 모두 **자동** 모드인지 확인 (`/admin/overlays`)
- [ ] 수동으로 바꾼 팀 점수 원복

## 4. 실제 방송 직전 체크 (5분 전)

- [ ] `/api/health` → `"ok": true`
- [ ] 지통실 상단 "동기화 시각"이 4초마다 바뀌는가
- [ ] 오늘 회차 상태가 "준비 완료", 큐시트·진행자별 대본 입력 완료
- [ ] 진행자 프롬프터: 각자 로그인 → `/admin/episodes/<회차>/prompter` (진행자 본인 대본이 기본 필터)
- [ ] 대기 화면 장면 → 방송 시작 → 회차 **방송 시작** → 게임 장면 전환

## 9. 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| 오버레이가 아무것도 안 보임 | 해당 오버레이가 "끄기" 모드인지, 표시할 내용(송출 속보·진행 중 회차)이 있는지. 브라우저로 URL 뒤에 `?bg=1` 붙여 열어 보기 |
| 흰/검은 배경이 덮임 | 사용자 지정 CSS 에 배경색이 들어가 있지 않은지, OBS 버전 |
| 반영이 5초 이상 늦음 | `/api/health` 의 `latencyMs`, OBS "보이지 않을 때 소스 종료" 꺼짐 여부, 네트워크 |
| 글자가 잘림/위치가 틀어짐 | 소스 크기가 1920×1080 인지, 캔버스 해상도, "화면에 맞추기" |
| 화면이 갑자기 사라짐 | 속보 "노출 종료 시각"이 지나 자동 종료된 것인지 `/admin/breaking` 전체 기록에서 확인 |
| 사이트 오류 화면(오류 코드 표시) | 오류 코드(digest)로 Vercel 로그 검색, `/api/health` 확인 |
